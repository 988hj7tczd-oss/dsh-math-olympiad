# 验证器失败模式清单（真实攻击面）

验证器（新鲜上下文的 subagent）拿到证明正文后，**逐条**对照本清单攻击。
每条都是"去找具体反例或缺口定位"，不是泛泛地说"逻辑 OK"。

## 0. 前置自检（对验证器自身）

- 我（验证器）拿到了证明正文还是思考链？只允许看到正文；若正文里混有
  "我试了""感觉""大概"等词，先报告"正文不干净"，拒绝背书。

## 1. 开放问题特化测试（最可靠红旗）

- 把定理/引理特化到知名开放问题（RH 及 ζ 函数族、孪生素数、哥德巴赫、
  Collatz、abc 猜想性质…）。若特化命题是开放问题而证明"顺带解决了"，
  证明**必有缺口**——报告缺口所在层（通常是用了一个未证的隐含断言）。
- 即使题目本身与开放问题无关，也要问：**"这个论证形式能不能证明 RH？"**
  能 → 必错；不能 → 指出是哪一步/哪个假设挡住了（这正是承重条件所在）。

## 2. 漏情形与 case split 覆盖

- 列出所有情形，检查并集是否覆盖命题全部条件；看等号/边界/端点是否单列。
- case split 里同一个缺口重复出现（两次以上）→ 警告：可能掩盖统一论证
  或统一反例（红旗第 4 条），要求合并重写后再审。

## 3. 隐含假设与未交代条件

- 是否悄悄引入：正性、可逆性、连续性、可微性、整数性、无重根、一般位置
  （三点不共线）、"WLOG 不失一般性"是否真的无损（置换、缩放、平移可以；
  丢弃条件不行）。
- 变量范围：n 是正整数还是任意实数？构造中分母是否可能为 0？

## 4. 退化与边界情形

- n≤3 的退化（共线、平凡界）、n=0/1、空集、单个元素、极限情形取不到等号。
- 组合题：空计数、重复计数（同一对象被两条路径各数一次）；双计数是否
  真的双射。

## 5. 循环论证与偷用结论

- 证明中是否用到"待证的结论本身"或其等价形式；
- 引理是否依赖主定理；两个命题是否互相引用而都没有独立基础。

## 6. 过度泛化（引理只在特例成立）

- 抽出的"一般引理"是否超范围使用？对引理先试 2×2 反例；若一般形式为假，
  找出本例哪个额外假设救了它（红旗第 3 条）。

## 7. 符号、方向与不等式方向

- 不等式方向是否在某一步翻号（负号、取倒数、取对数、单调性方向）；
- 上下界是否"比反了"（证出的界是否真的比目标强）；
- 下标/索引：n 与 n+1、i 与 j 的符号错误（归纳步最常见的死因）。

## 8. 未证步骤与"显然"

- 所有"显然""容易看出""由对称性"逐条点名：它是否真可由已证内容推出？
  对称性是否真实存在（变量真可交换？还是只有部分对称）？

## 9. 与已知构造/反例冲突

- 用列表中的已知反例族逐一特化：调和级数型、交错级数、熵/计数极端、
  几何极端（退化三角形、趋于无穷、趋于边界）。
- 若证明的结论与已知定理（二项式定理、LTE、Wilson、Fermat 小定理、
  Pigeonhole 变体…）冲突，报告冲突并定位。

## 输出协议

```
致命缺口（阻止结论成立）：[编号] 具体反例或缺口定位
非致命缺口（不影响结论但需修补）：[编号] 定位
通过项：[对哪些失败模式确认无缺口]
结论：证明【成立 / 不成立 / 无法判定】
```

- 有致命缺口必须给**最小反例**（能手工核验的规模）。
- 禁止输出"整体看来合理"之类的泛泛结论；没有具体定位就不要写"通过"。
